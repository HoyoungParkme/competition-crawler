# PRD — AI·개발 대회 일배치 수집기

## 1. 목표

#### G1 대회를 찾아 노션에 옮겨적는 손일을 없앤다

#### G2 지금 방식으로는 놓치던 대회까지 걸리게 한다

#### G3 노션에 남는 것이 지금 지원 가능하고 관심 분야인 대회만이 되게 한다

#### G4 사람이 손대지 않아도 매일 돌게 한다

## 2. 비목표

| 비목표 | 이유 |
|---|---|
| 대회 조회용 화면을 따로 만들지 않는다 | 노션 `대회목록` DB가 이미 그 역할을 한다 [[CCR-RFQ-001#Q3]] |
| 새 대회를 메일·메신저로 알리지 않는다 | 노션이 갱신되어 있으면 충분하다 [[CCR-RFQ-001#Q6]] |
| `상태` 컬럼을 프로그램이 바꾸지 않는다 | 참가 여부는 사람의 판단이다 [[CCR-RFQ-001#Q3]] |
| 이미 노션에 있는 행을 고치거나 지우지 않는다 | 마감된 기존 행의 정리는 사용자 몫이다 [[CCR-RFQ-001#Q11]] |
| 대회 상세 본문을 수집하거나 요약하지 않는다 | 링크가 있으면 사용자가 직접 읽는다. 소스마다 상세 페이지를 파면 비용이 급등한다 |
| 참가 신청·제출을 자동화하지 않는다 | 이 도구의 일은 찾아 주는 데까지다 |
| 대회 하나만을 위한 전용 사이트를 개별로 크롤링하지 않는다 | 목록이 갱신되지 않아 매일 돌 이유가 없다 [[CCR-RFQ-001#Q4]] |
| 과거에 마감된 대회를 아카이브로 쌓지 않는다 | 참가할 수 없는 대회는 판단에 쓸모가 없다 [[CCR-RFQ-001#Q11]] |

## 3. 요구사항

### 3.1 기능

#### R1 여섯 소스에서 대회 목록을 수집한다

근거: [[CCR-RFQ-001#Q4]]

event-us.kr · DACON · Kaggle · wevity · AI팩토리 · 콘테스트코리아에서 현재 열려 있는 대회 목록을 가져온다.

event-us는 분야(`category`)로 좁히지 않는다. 좁히면 사용자가 지금 챙기고 있는 대회가 걸러진다([[CCR-RFQ-001#Q2]]). 행사유형이 `대회/공모전`인 것을 전부 가져온 뒤 뒤쪽 단계에서 거른다.

- [ ] 여섯 소스 각각에서 목록을 가져온다
- [ ] event-us는 `event_type=대회/공모전`만 걸고 `category`는 걸지 않는다
- [ ] 소스별로 몇 건을 가져왔는지 셀 수 있다

#### R2 소스가 달라도 하나의 형식으로 정규화한다

근거: [[CCR-RFQ-001#Q4]], [[CCR-RFQ-001#Q3]]

소스마다 필드 이름과 날짜 형식이 다르다. 노션에 넣기 전에 공통 형식으로 맞춘다. 최소한 대회명·상세링크·접수시작일·접수마감일·출처가 채워져야 한다.

날짜는 **접수 기준**이며 **KST로 변환한 뒤 날짜만 취한다.** 노션에 손으로 넣은 5건과 event-us 필드를 대조해 확인한 결과다.

| 노션 컬럼 | event-us 필드 | 대조 결과 |
|---|---|---|
| 시작일 | `register_start_date` | 5건 중 3건 일치 (나머지 2건은 사용자가 달리 적음) |
| 마감일 | `register_due_date` | **5건 전부 일치** |

`close_date`(행사 종료일)를 마감일로 쓰면 어긋난다. `2026 국립공원 위성 모니터링 AI 챌린지`는 `register_due_date`가 10/6, `close_date`가 10/14로 8일 차이가 나고 노션에 적힌 값은 10/6이다.

- [ ] 모든 소스의 결과가 같은 형식으로 나온다
- [ ] 대회명·상세링크·접수마감일·출처가 비어 있지 않다
- [ ] 날짜는 KST 기준 날짜로 저장된다
- [ ] event-us의 마감일은 `register_due_date`에서 온다
- [ ] 접수시작일이 없는 소스는 빈 값으로 두고, 그 때문에 적재가 실패하지 않는다

#### R3 마감이 지난 대회는 버린다

근거: [[CCR-RFQ-001#Q11]]

배치가 도는 시점을 기준으로 접수마감일이 이미 지난 대회는 노션에 넣지 않는다. 마감일을 알 수 없는 대회는 버리지 않고 남긴다 — 놓치는 쪽이 더 나쁘다.

- [ ] 접수마감일이 실행 시점(KST) 이전인 대회는 적재되지 않는다
- [ ] 마감일을 알 수 없는 대회는 적재된다
- [ ] Kaggle의 상시 연습용 대회(`Getting Started`·`Playground`)는 마감일과 무관하게 제외된다

#### R4 관심 분야가 아닌 대회는 걸러낸다

근거: [[CCR-RFQ-001#Q12]]

[[#R1]]에서 넓게 가져오므로 관심 밖의 건이 섞인다. event-us만 봐도 마감 전 112건 중 창업이 39건이었고 사진 공모전·영상제·교육과정 모집도 들어 있었다. 이것을 OpenAI 모델로 한 건씩 판별한다.

잠정 기준은 아래와 같다. 첫 실행 결과를 보고 조정한다.

| | 예 |
|---|---|
| 남긴다 | AI·머신러닝·데이터 분석 경진대회, 해커톤, 소프트웨어·개발 공모전, 데이터 활용 공모전, 알고리즘 대회, AI 주제 논문 경진대회 |
| 버린다 | 창업·IR 경진대회, 사진·영상·디자인·문학 공모전, AI와 무관한 논문 공모, 교육과정·부트캠프 모집, 세미나·컨퍼런스 |

- [ ] 판별 결과가 남긴다/버린다 둘 중 하나로 나온다
- [ ] 판별에 쓴 근거를 로그에서 확인할 수 있다
- [ ] 판별이 실패한 대회는 버리지 않고 남긴다
- [ ] 이미 판별한 대회를 다시 판별하지 않는다

#### R5 이미 노션에 있는 대회는 다시 넣지 않는다

근거: [[CCR-RFQ-001#Q3]]

배치가 매일 돌고 같은 대회가 여러 소스에 올라오므로 중복이 두 방향으로 생긴다. 하나는 어제 넣은 것을 오늘 또 넣는 것이고, 다른 하나는 같은 대회가 서로 다른 소스에서 각각 들어오는 것이다.

사용자가 손으로 넣어 둔 기존 행과도 겹치면 안 된다. 기존 행은 링크가 전용 사이트를 가리키는 경우가 있어 링크만으로는 판정되지 않는다. `2026 Big Data 활용 대회`는 노션 링크가 `dxchallenge.co.kr`인데 event-us에도 같은 대회가 있다.

- [ ] 같은 대회를 이틀 연속 실행해도 행이 하나만 남는다
- [ ] 여러 소스에 올라온 같은 대회가 행 하나로만 들어간다
- [ ] 사용자가 손으로 넣어 둔 행과 겹치는 대회는 새로 추가되지 않는다

#### R6 노션 `대회목록` DB에 새 대회를 등록한다

근거: [[CCR-RFQ-001#Q3]], [[CCR-RFQ-001#Q7]]

기존 컬럼에 더해 `출처`와 `수집일`을 추가한다. 기존 행은 건드리지 않아 두 컬럼이 빈 값으로 남는다.

| 노션 컬럼 | 채우는 값 |
|---|---|
| 기타 (title) | 대회명 |
| 링크 | 상세 페이지 주소 |
| 시작일 | 접수 시작일 |
| 마감일 | 접수 마감일 |
| 결과날 | 채우지 않는다. 어느 소스에도 결과 발표일이 없다 |
| 상태 | `시작 전`으로 넣는다. 이후 사용자가 관리한다 |
| 출처 | 어느 소스에서 온 건인지 |
| 수집일 | 적재한 날 |

- [ ] `출처`·`수집일` 컬럼이 DB에 존재한다
- [ ] 새 대회가 위 표대로 채워져 등록된다
- [ ] `상태`는 `시작 전`으로만 설정되고 이후 실행에서 덮어쓰지 않는다
- [ ] 기존 행의 어떤 값도 바뀌지 않는다

#### R7 매일 09:00 KST에 자동으로 실행된다

근거: [[CCR-RFQ-001#Q10]], [[CCR-RFQ-001#Q5]]

GitHub Actions 스케줄로 돈다. 손으로도 돌릴 수 있어야 한다.

- [ ] 매일 09:00 KST에 실행된다
- [ ] 저장소에서 수동으로 실행할 수 있다
- [ ] 노션에 쓰지 않고 결과만 확인하는 모드로 돌릴 수 있다

#### R8 실행 결과를 확인할 수 있다

근거: [[CCR-RFQ-001#Q5]]

알림은 보내지 않으므로([[CCR-RFQ-001#Q6]]) 이상을 알아채는 유일한 통로가 실행 기록이다.

- [ ] 소스별 수집 건수, 단계별로 걸러진 건수, 최종 적재 건수가 남는다
- [ ] 실패한 소스와 그 사유가 남는다
- [ ] 적재된 대회의 이름이 남는다

#### R9 소스 하나가 실패해도 나머지는 적재된다

근거: [[CCR-RFQ-001#Q4]]

소스 여섯 중 셋은 마크업 변경에 깨질 수 있는 방식이다. 하나가 깨졌다고 그날 수집이 통째로 날아가면 안 된다.

- [ ] 한 소스가 예외를 던져도 나머지 소스의 결과가 노션에 적재된다
- [ ] 실패한 소스가 [[#R8]]의 기록에 남는다
- [ ] 모든 소스가 실패하면 실행이 실패로 끝난다

### 3.2 비기능

#### N1 운영 비용

유료로 나가는 것은 [[#R4]]의 OpenAI 호출뿐이다. 공개 저장소라 Actions는 무료이고 Kaggle API도 무료다.

- [ ] 월 운영비가 미화 1달러 미만이다

#### N2 배치 소요 시간

- [ ] 한 번 실행이 10분 이내에 끝난다

#### N3 비밀값 취급

근거: [[CCR-RFQ-001#Q9]]

공개 저장소라 값이 코드나 로그에 섞이면 그대로 노출된다.

- [ ] 노션 토큰·OpenAI 키·Kaggle 자격증명이 GitHub Secrets에만 있다
- [ ] 저장소 파일과 실행 로그 어디에도 값이 나타나지 않는다

#### N4 수집 예의

상대 서버에 부담을 주지 않는다.

- [ ] 요청 사이에 간격을 둔다
- [ ] 식별 가능한 User-Agent를 보낸다
- [ ] 각 사이트의 `robots.txt`를 확인하고 금지된 경로를 요청하지 않는다

#### N5 재실행 안전성

실패한 날 다시 돌리는 일이 생긴다.

- [ ] 같은 날 여러 번 실행해도 노션 결과가 한 번 실행한 것과 같다
- [ ] 노션 적재 도중 끊겨도 다음 실행에서 이어서 채워진다

## 4. 성공지표

| 지표 | 목표 | 재는 법 |
|---|---|---|
| 손으로 옮겨적은 대회 수 | 월 0건 | 사용자가 직접 추가한 행 수 |
| 놓치지 않는 정도 | 사용자가 따로 발견한 대회 중 배치가 이미 잡아 둔 비율 90% 이상 | 사용자가 새 대회를 알게 됐을 때 노션에 이미 있는지 확인 |
| 잡음 정도 | 새로 적재된 건 중 관심 없는 건의 비율 20% 이하 | 적재 후 사용자가 지우는 행의 비율 |
| 배치 성공률 | 최근 30회 중 28회 이상 성공 | Actions 실행 이력 |
| 소요 시간 | 10분 이내 | Actions 실행 시간 |
| 운영비 | 월 1달러 미만 | OpenAI 사용량 |

첫 기준선은 이미 잡혀 있다. 노션에 등록된 10건 중 9건이 event-us 한 곳에서만도 검색된다. 나머지 1건(`2026 한국관광 데이터랩 활용 경진대회`)은 여섯 소스 어디에도 없어 이번 범위로는 잡히지 않는다.

## 5. ID 체계와 날짜 매핑

대회 하나는 **출처 + 그 출처에서의 원천 ID**로 식별한다. event-us는 `id`, DACON은 `cpt_id`, Kaggle은 대회 `ref`가 그 값이다. 이것이 [[#R5]]의 첫 번째 중복(어제 넣은 것을 오늘 또 넣는 것)을 막는다.

두 번째 중복 — 같은 대회가 서로 다른 소스에서 들어오는 것 — 은 원천 ID로 풀리지 않는다. 판정 방식은 미결이다.

날짜는 전부 **KST 기준 날짜(시각 없음)** 로 다룬다. 소스가 주는 값은 `+00:00` 오프셋이 붙어 있으나 실제로는 KST 시각이라 변환 없이 날짜만 취하면 하루씩 어긋난다.

## 6. 미결사항

- [ ] [[#R5]]의 소스 간 중복 판정 방식. 대회명 정규화 후 비교할지, 주최·마감일을 같이 볼지, LLM에 맡길지
- [ ] [[#R4]]에 쓸 OpenAI 모델과 API 키
- [ ] AI팩토리와 콘테스트코리아의 목록 추출 방식. 정적 요청만으로는 구조화된 레코드를 얻지 못했다 ([[CCR-RFQ-001#Q4]])
- [ ] Kaggle 자격증명 발급, 그리고 영문 대회명을 그대로 둘지 옮길지
- [ ] 노션 인테그레이션 토큰 발급과 `대회목록` DB 접근 권한 부여
- [ ] [[#R8]]의 기록을 Actions 로그로만 둘지, 저장소에 파일로도 남길지
- [ ] 첫 실행에서 한꺼번에 들어올 물량. event-us만 마감 전 112건이고 여섯 소스면 더 된다. 전부 넣을지, 마감이 가까운 것부터 일부만 넣을지
