# RFQ — 요구·인터뷰

## 1. 배경과 동기

사용자는 AI·개발 분야의 대회와 공모전에 꾸준히 참가한다. 지금은 event-us.kr 검색 화면을 직접 열어 조건을 걸고 눈으로 훑은 뒤, 참가할 만한 것을 노션 `대회목록` DB에 손으로 옮겨 적는다. 노션에는 대회명·링크·시작일·마감일·결과날·상태를 두고, 상태(시작 전 / 진행 중 / 제출 / 완료)는 직접 갱신한다.

이 방식은 두 가지가 걸린다. 찾는 일이 매번 반복되고, 며칠 사이트를 안 보면 마감이 지난 뒤에 대회의 존재를 알게 된다. 사용자는 이 찾기·옮겨적기를 매일 자동으로 도는 프로그램에 넘기고, 자신은 "무엇에 참가할지" 판단만 남기기를 원한다.

## 2. 명세 체인

이 문서가 체인의 시작이다. 아래 단계로 이어진다.

| 단계 | 타입 | 이 프로젝트에서 다루는 것 |
|---|---|---|
| 2 | PRD | 목표·비목표·기능/비기능 요구·성공지표 |
| 3 | SCN | 일배치 1회 실행 시나리오, 신규/중복/변경 건 처리 |
| 4 | UC | 수집·정규화·관련도 판별·중복판정·노션 반영 유스케이스 |
| 5 | INFRA | GitHub Actions 스케줄, 시크릿, 실행·재시도·로그 |
| 6 | DOM | 대회 도메인 모델, 소스별 어댑터 구조, 저장 스키마 |
| 8 | API | 외부 연동 규격 — event-us 검색 API, Kaggle API, OpenAI API, Notion API |
| 9 | SEQ | 배치 실행 흐름 |
| 10 | MS | 소스별 구현 순서와 릴리스 단위 |

7단계 UI는 다루지 않는다. 조회 화면은 노션이 대신한다.

## 3. 요구 사항

#### Q1 매일 자동으로 대회를 찾아 줄 것

"AI나 개발 대회를 많이 나가는데, 이걸 자동으로 일배치 돌아서 크롤링해 주는 프로그램을 만들었으면 한다." 지금은 사람이 사이트에 들어가서 찾는 일을 하루 한 번 자동 실행으로 대체한다.

#### Q2 지금 쓰는 검색 조건이 출발점이되, 그대로 쓰지는 않는다

사용자가 평소 쓰는 조건은 event-us.kr의 다음 검색 URL이다.

```
https://event-us.kr/search?query=ai ax&eventtype=대회/공모전&category=IT/프로그래밍&costmin=무료&order=score&date=모든날&page=1
```

검색어 `ai ax`, 행사유형 `대회/공모전`, 분야 `IT/프로그래밍`, 비용 `무료`.

이 조건을 그대로 자동화하면 사용자가 지금 챙기고 있는 대회를 놓친다. 노션에 등록된 10건을 이 조건으로 검색해 본 결과 3건만 잡혔다. 나머지 중 5건은 **event-us에 분명히 있고 행사유형도 `대회/공모전`이 맞는데도** 분야 값이 `IT/프로그래밍`이 아니라서 걸러졌다.

| 노션에 있는 대회 | event-us 분야 값 |
|---|---|
| 제9회 디테크(D-TECH) 공모전 | 인문/사회 |
| 2026 국립공원 위성 모니터링 AI 챌린지 | 과학기술 |
| 제5회 기아 PBV 아이디어 공모전 | 기타 |
| 2026 제3회 국가지식정보 통합플랫폼 디지털집현전 우수사례 공모전 | 과학기술 |
| 2026 데이터·AI 혁신 챌린지 통합경진대회 | 과학기술 |

따라서 분야로 좁히는 방식은 쓰지 않는다. 넓게 가져온 뒤 관련도로 거른다([[#Q12]]).

#### Q3 결과는 노션 `대회목록` DB에 자동 등록

"기존에는 사진처럼 내가 관리하고 있었다." 수집 결과를 별도 화면이 아니라 이미 쓰고 있는 노션 DB에 그대로 쌓는다. 이미 등록된 대회는 다시 추가하지 않는다. 상태(시작 전 / 진행 중 / 제출 / 완료)는 지금처럼 사용자가 직접 관리하며, 프로그램이 건드리지 않는다.

#### Q4 수집 소스는 여섯 곳으로 한다

"일단 수집하는 소스(출처)가 되는 부분을 어디서 할지 조사 먼저 하자." 후보 15곳을 조사한 결과를 보고 여섯 곳으로 확정했다.

| 소스 | 성격 | 접근 방식 |
|---|---|---|
| event-us.kr | 행사·대회 종합 플랫폼 | 공개 검색 JSON API |
| DACON | AI·데이터 경진대회 전문 (국내) | 목록 페이지의 서버 렌더링 페이로드 |
| Kaggle | AI·데이터 경진대회 전문 (글로벌) | 공식 REST API. HTTP Basic 인증 |
| wevity.com | 공모전 포털 | 정적 HTML 목록 |
| AI팩토리 | AI 경진대회 전문 | 정적 HTML 목록 (서버 렌더링) |
| 콘테스트코리아 | 공모전 포털 | 정적 HTML 목록 |

여섯 곳 모두 헤드리스 브라우저 없이 가져올 수 있다. 이것이 배치 소요 시간과 비용을 누르는 전제가 된다.

##### 선정 기준

세 가지를 봤다. ① 목록이 주기적으로 갱신되는가 — 매일 도는 배치라 새 건이 안 나오면 의미가 없다. ② 자동으로 추출할 수 있는가. ③ 사용자가 실제로 원하는 종류의 대회가 거기 있는가 — 노션에 이미 등록된 10건을 각 소스에서 역으로 찾아 검증했다.

제외 사유는 세 갈래다. 전용 사이트 셋은 애초에 목록이 없어 배치의 대상이 아니다. `kdata.or.kr`과 `event.wanted.co.kr`은 그 대회가 event-us에서 이미 잡혀 별도 소스로 둘 이유가 없다. 나머지는 원하는 종류가 없거나 자동 추출이 안 된다.

##### AI팩토리와 콘테스트코리아를 정적 추출로 확정한 경위

처음 조사에서는 둘 다 "구조화된 레코드를 못 얻었다"고 적었으나, 다시 확인해 보니 도구를 잘못 쓴 것이었다.

| 소스 | 처음 실패한 이유 | 실제 |
|---|---|---|
| AI팩토리 | Next.js의 RSC flight 페이로드만 뒤졌다 | 서버 렌더링 결과가 평문 HTML로 나온다. 제목·상태(`진행중`)·유형(`경진대회`)·상금·주제가 모두 마크업 안에 있다 |
| 콘테스트코리아 | 본문 목록이 아니라 사이드바 인기글을 잡는 셀렉터를 썼다 | 목록 항목의 제목이 `<a>` 안 평문이다 |

##### Kaggle 접근 경로

내부 엔드포인트는 reCAPTCHA로 막혀 있고 목록 페이지는 SPA라 HTML에 데이터가 없다. 공식 REST API만 열려 있으며 HTTP Basic 인증으로 동작하는 것을 확인했다(자격증명 없이 401). 계정 설정에서 무료로 토큰을 발급받아 쓴다.

#### Q5 일배치는 GitHub Actions에서 돈다

PC가 꺼져 있어도 돌아야 하고, 실행 로그가 남아야 한다. 별도 서버나 로컬 cron 대신 GitHub Actions를 쓴다.

#### Q6 알림은 필요 없다

새 대회를 발견해도 메일이나 메신저로 알리지 않는다. 노션이 갱신되어 있으면 충분하며, 확인은 사용자가 직접 들어가서 한다.

#### Q7 노션 DB에 컬럼을 추가해도 된다

`출처`(어느 사이트에서 온 건인지)와 `수집일` 두 컬럼을 추가한다. 기존에 손으로 넣은 행은 그대로 두고 두 컬럼을 빈 값으로 남긴다.

#### Q8 명세는 싱크독으로 관리한다

"싱크독 MCP를 이용해서 개발할 거다." 설계 산출물은 싱크독 11단계 문서 체계에 넣고, 코드보다 명세를 먼저 확정한다.

#### Q9 저장소는 공개로 둔다

GitHub 계정 `HoyoungParkme` 아래 `competition-crawler` 공개 저장소를 쓴다. 비밀값은 본문에 두지 않고 저장소 Secrets에 넣는다.

| 시크릿 | 쓰는 곳 |
|---|---|
| 노션 인테그레이션 토큰 | [[#Q3]] 노션 적재 |
| OpenAI API 키 | [[#Q12]] 관련도 판별 |
| Kaggle 사용자명·API 키 | [[#Q4]] Kaggle 수집 |

#### Q10 배치는 한국 시간 매일 오전 9시

"배치는 한국 시간 기준 오전 9시로 가자." 하루 한 번, 09:00 KST에 실행한다.

#### Q11 마감된 대회는 적재하지 않는다

"마감된 대회는 적재하지 마." 수집 시점에 이미 마감일이 지난 대회는 노션에 넣지 않는다.

이미 노션에 들어가 있는 행이 마감되는 경우는 프로그램이 손대지 않는다. "기존에 적재된 거에서 마감된 건 사용자가 알아서 닫기를 하겠지." 마감된 기존 행의 정리는 사용자 몫이다.

#### Q12 관련 없는 대회는 LLM으로 걸러낸다

분야 필터를 쓰지 않으면([[#Q2]]) 창업 경진대회·사진 공모전·영상제·교육과정처럼 관심 밖의 건이 함께 들어온다. event-us만 봐도 접수마감 전 대회가 2026-09-16 기준 56건인데 그중 창업이 14건으로 가장 많았다.

이것을 LLM으로 판별한다. "LLM으로 판별. OpenAI를 쓸 거야." 대회 하나하나에 대해 AI·데이터·개발 분야 대회인지 판단하고, 아닌 것은 노션에 넣지 않는다. 쓸 모델은 [[#Q14]]에서 정한다.

Kaggle에는 상시 열려 있는 연습용 대회(`Getting Started`·`Playground`)가 섞여 있다. 마감일이 먼 미래로 잡혀 있어 [[#Q11]]의 마감 필터로는 걸러지지 않으므로 이쪽도 함께 제외 대상으로 다룬다.

#### Q13 Kaggle 대회명은 영문 원문 그대로 둔다

Kaggle은 대회명이 영문이다. 번역하지 않고 원문 그대로 노션에 넣는다. 대회명이 고유명사에 가까워 옮기면 검색도 안 되고 남과 이야기할 때도 안 통한다.

#### Q14 관련도 판별에는 OpenAI의 싼 모델을 쓴다

"그냥 OpenAI 싼 거 쓰면 될 듯." [[#Q12]]의 판별은 "이것이 AI·개발 분야 대회인가"를 가르는 분류 작업이라 소형 모델로 충분하다. 정확한 모델 이름은 구현 시점에 그때의 최신 목록에서 고르고, 설정값으로 빼서 바꿔 끼울 수 있게 둔다.

#### Q15 실행 기록은 두 곳에 남긴다

알림이 없으므로([[#Q6]]) 실행 기록이 이상을 알아채는 유일한 통로다. GitHub Actions 로그와 저장소 안의 요약 파일 양쪽에 남긴다.

Actions 로그는 보관 기간이 지나면 사라지고 과거와 견주려면 실행을 하나씩 열어야 한다. 저장소에 날짜별 소스 건수를 쌓아 두면 그 비교가 자동으로 된다. 그래서 소스가 오류 없이 0건을 준 날을 "새 대회가 없던 날"이 아니라 "파서가 깨진 날"로 알아챌 수 있다 — 어제까지 꾸준히 건수를 내던 소스가 오늘 0건이면 경고로 남긴다.

## 4. 사용자와 환경

| 항목 | 내용 |
|---|---|
| 사용자 | 개인 1인. 대회 참가 당사자이자 이 프로그램의 유일한 사용자이며 개발자 |
| 사용 맥락 | 하루에 한 번 노션을 열어 새로 쌓인 대회를 훑고, 참가할 것의 상태를 직접 바꾼다 |
| 조회 수단 | 노션 `대회목록` DB (MAIN 페이지 하위). 별도 화면을 만들지 않는다 |
| 실행 환경 | GitHub Actions (`HoyoungParkme/competition-crawler`, public) |
| 개발 환경 | WSL2 / Ubuntu, Python 3.12, uv, Node 24 |
| 비용 | 최소 비용으로 운영한다. GitHub Actions는 공개 저장소라 무료이고 Kaggle API도 무료다. 유료로 나가는 것은 [[#Q12]]의 OpenAI 호출뿐이다 |

노션 `대회목록` DB의 현재 스키마는 아래와 같다. 데이터 모델의 출발점이다.

| 속성 | 타입 | 값 |
|---|---|---|
| 기타 | title | 대회명 |
| 링크 | url | 상세 페이지 주소 |
| 시작일 | date | |
| 마감일 | date | |
| 결과날 | date | |
| 상태 | status | 시작 전 / 진행 중 / 제출 / 완료 |

## 5. 첫 프로젝트

싱크독을 처음 적용하는 프로젝트다. 사용자가 혼자 쓰는 도구라 외부 이해관계자가 없고, 명세가 틀렸을 때 되돌리는 비용이 낮다. 11단계를 전부 두껍게 채우기보다 배치 한 번이 도는 데 필요한 문서부터 확정하고, 소스가 늘어날 때 DOM·MS를 덧붙이는 방식으로 간다.
