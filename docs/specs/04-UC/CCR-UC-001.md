# USECASE (Cockburn)

## 0. 이 문서의 형식

Cockburn 형식을 따른다. 사용자 목표 수준은 한 번에 끝나는 목표 하나를, 하위기능 수준은 그 안에서 되풀이되는 조각을 적는다.

이 도구는 사람이 조작하는 화면이 없다. 주 액터가 사람이 아닌 유스케이스가 중심이고([[#UC-A1]]), 사람이 나오는 것은 결과를 쓰는 쪽([[#UC-A2]])과 고치는 쪽([[#UC-A3]])이다.

`대회`는 한 소스에서 온 공고 하나를 말한다. 같은 대회가 여러 소스에 올라온 것은 [[#UC-S4]]에서 하나로 묶인다.

## 1. 액터

| 액터 | 종류 | 하는 일 |
|---|---|---|
| 스케줄러 | 주 액터 (시스템) | 매일 09:00 KST에 배치를 깨운다. GitHub Actions |
| 참가자 | 주 액터 (사람) | [[CCR-SCN-001#P1]]. 노션을 열어 대회를 고르고 `상태`를 바꾼다 |
| 관리자 | 주 액터 (사람) | [[CCR-SCN-001#P2]]. 배치가 깨졌을 때 고친다. 참가자와 같은 사람이지만 역할이 다르다 |
| 대회 소스 | 보조 액터 | event-us · DACON · Kaggle · wevity · AI팩토리 · 콘테스트코리아 |
| 판별 모델 | 보조 액터 | OpenAI. 대회가 관심 분야인지 답한다 |
| 노션 | 보조 액터 | `대회목록` DB. 읽고 쓴다 |
| 적재 이력 | 보조 액터 | 저장소에 두는 상태 파일. 지금까지 적재한 대회의 키를 기억한다 |

## 2. 사용자 목표 수준 유스케이스

#### UC-A1 하루치 대회를 수집해 노션에 반영한다

| 항목 | 내용 |
|---|---|
| 범위 | 대회 수집 배치 |
| 수준 | 사용자 목표 |
| 주 액터 | 스케줄러 |
| 이해관계자와 관심사 | 참가자 — 그날 뜬 관심 분야 대회가 빠짐없이 노션에 있기를 바란다. 관리자 — 무엇이 실패했는지 남기를 바란다. 대회 소스 — 과한 요청을 받지 않기를 바란다 |
| 사전조건 | 노션 토큰·OpenAI 키·Kaggle 자격증명이 설정되어 있다. `대회목록` DB에 `출처`·`수집일` 컬럼이 있다 |
| 최소 보장 | 노션의 기존 행이 바뀌지 않는다. 실행 기록이 남는다 |
| 성공 보장 | 접수마감 전이고 관심 분야이며 아직 모르는 대회가 노션에 행 하나씩으로 들어간다. 적재 이력이 갱신된다 |
| 트리거 | 매일 09:00 KST. 관리자의 수동 실행으로도 시작된다 |
| 패키지 | 배치 |
| 포함(include) | [[#UC-S1]] · [[#UC-S2]] · [[#UC-S3]] · [[#UC-S4]] · [[#UC-S5]] · [[#UC-S6]] · [[#UC-S7]] |
| 확장점(extension point) | — |
| 일반화 | — |

**기본 흐름**

1. 스케줄러가 배치를 깨운다.
2. 여섯 소스에서 대회 목록을 가져온다([[#UC-S1]]).
3. 소스마다 다른 결과를 하나의 형식으로 맞춘다([[#UC-S2]]).
4. 접수마감이 지난 대회를 버린다([[#UC-S3]]).
5. 이미 아는 대회를 뺀다([[#UC-S4]]).
6. 남은 대회가 관심 분야인지 판별한다([[#UC-S5]]).
7. 관심 분야로 판정된 대회를 노션에 넣고 적재 이력에 기록한다([[#UC-S6]]).
8. 실행 기록을 남긴다([[#UC-S7]]).
9. 성공으로 끝낸다.

첫 실행에서 후보가 수백 건이어도 나누지 않고 한 번에 처리한다. 접수마감 전인 것만 남으므로 물량이 무한정 늘지 않는다.

**확장**

- **2a. 소스 하나가 실패한다**
  - 2a1. 그 소스의 결과를 빈 목록으로 두고 실패 사유를 기록한다.
  - 2a2. 3으로 간다. 나머지 소스의 결과는 평소대로 처리된다.
- **2b. 여섯 소스가 모두 실패한다**
  - 2b1. 실행 기록을 남기고 실패로 끝낸다. 네트워크나 설정이 통째로 잘못된 경우라 조용히 넘어가지 않는다.
- **5a. 노션을 읽지 못한다**
  - 5a1. 중복 판정의 근거가 없으므로 적재를 하지 않는다.
  - 5a2. 실행 기록을 남기고 실패로 끝낸다.
- **6a. 판별 모델 호출이 실패한다**
  - 6a1. 판별하지 못한 대회를 관심 분야로 보고 남긴다([[#UC-S5]] 3a).
  - 6a2. 7로 간다.
- **7a. 노션에 쓰는 도중 끊긴다**
  - 7a1. 그때까지 넣은 대회만 적재 이력에 기록한다.
  - 7a2. 실행 기록을 남기고 실패로 끝낸다. 남은 것은 다음 실행이 채운다([[#UC-A3]]).

**연관**: [[CCR-PRD-001#R1]] · [[CCR-PRD-001#R7]] · [[CCR-PRD-001#R9]] · [[CCR-PRD-001#N5]] · [[CCR-SCN-001#S1]] · [[CCR-SCN-001#S2]]

#### UC-A2 새로 들어온 대회를 훑고 참가할 것을 고른다

| 항목 | 내용 |
|---|---|
| 범위 | 노션 `대회목록` |
| 수준 | 사용자 목표 |
| 주 액터 | 참가자 |
| 이해관계자와 관심사 | 참가자 — 마감 전에 알고 싶고, 관심 없는 것에 시간을 쓰고 싶지 않다 |
| 사전조건 | [[#UC-A1]]이 최소 한 번 성공했다 |
| 최소 보장 | 참가자가 손으로 넣은 행과 바꿔 둔 `상태`가 보존된다 |
| 성공 보장 | 참가자가 어느 소스 사이트도 열지 않고 그날의 대회를 파악한다 |
| 트리거 | 참가자가 아침에 노션을 연다 |
| 패키지 | 조회 |
| 포함(include) | — |
| 확장점(extension point) | — |
| 일반화 | — |

**기본 흐름**

1. 참가자가 노션 `대회목록`을 연다. 목록은 마감일 오름차순이다.
2. `수집일`이 오늘인 행을 훑는다.
3. 관심이 가는 대회의 `링크`를 열어 상세를 읽는다.
4. 참가하기로 한 대회의 `상태`를 `진행 중`으로 바꾼다.
5. 관심 없는 대회의 행을 지운다.

**확장**

- **2a. 오늘 들어온 행이 없다**
  - 2a1. 새 대회가 없던 날인지 배치가 죽은 날인지 구분되지 않는다. 참가자가 관리자 역할로 [[#UC-A3]]을 한다.
- **5a. 지운 대회가 다음 실행에서 다시 들어온다**
  - 5a1. 일어나지 않는다. [[#UC-S4]]가 노션 현재 행뿐 아니라 적재 이력도 보므로, 지운 행의 키가 이력에 남아 다시 들어오지 않는다.
- **3a. 마감일이 연장된 대회가 있다**
  - 3a1. 노션의 `마감일`은 처음 적재한 값 그대로다. 참가자가 상세 링크를 열어야 안다. 4장 열린 물음에 남긴다.

**연관**: [[CCR-PRD-001#R6]] · [[CCR-SCN-001#S1]] · [[CCR-SCN-001#S4]] · [[CCR-SCN-001#S7]]

#### UC-A3 깨진 배치를 진단하고 다시 돌린다

| 항목 | 내용 |
|---|---|
| 범위 | 대회 수집 배치 |
| 수준 | 사용자 목표 |
| 주 액터 | 관리자 |
| 이해관계자와 관심사 | 관리자 — 무엇이 왜 실패했는지 기록만 보고 알고 싶다. 참가자 — 하루 빠진 대회가 다음 실행에서 들어오기를 바란다 |
| 사전조건 | 실행 기록이 남아 있다 |
| 최소 보장 | 진단 과정에서 노션이 바뀌지 않는다 |
| 성공 보장 | 실패 원인이 밝혀지고, 다시 돌린 결과가 한 번 성공한 것과 같아진다 |
| 트리거 | 노션에 며칠째 새 행이 없다. 또는 Actions 실행이 실패로 끝났다 |
| 패키지 | 운영 |
| 포함(include) | [[#UC-S7]] |
| 확장점(extension point) | — |
| 일반화 | — |

**기본 흐름**

1. 관리자가 실행 기록을 연다([[#UC-S7]]).
2. 소스별 수집 건수를 본다. 평소와 다른 소스를 찾는다.
3. 실패한 소스와 사유를 확인한다.
4. 노션에 쓰지 않는 모드로 배치를 돌려 무엇이 들어갈지만 본다.
5. 원인을 고친다.
6. 배치를 수동으로 다시 돌린다.
7. 앞 실행에서 이미 들어간 대회는 [[#UC-S4]]에 걸려 빠지고, 못 넣은 것만 들어간다.

**확장**

- **2a. 어느 소스도 실패하지 않았는데 건수가 0이다**
  - 2a1. 소스가 살아 있으면서 빈 결과를 준 경우다. 실패와 구분되지 않는다. 관리자가 소스 사이트를 직접 열어 확인한다. 4장 열린 물음에 남긴다.
- **6a. 같은 날 여러 번 돌린다**
  - 6a1. 노션 결과가 한 번 돌린 것과 같다. [[#UC-S4]]가 매번 현재 상태를 근거로 판정하기 때문이다.

## 3. 하위기능 수준 유스케이스

#### UC-S1 소스에서 대회 목록을 가져온다

| 항목 | 내용 |
|---|---|
| 범위 | 수집 |
| 수준 | 하위기능 |
| 주 액터 | 배치 |
| 이해관계자와 관심사 | 대회 소스 — 짧은 시간에 몰린 요청을 받지 않기를 바란다 |
| 사전조건 | 그 소스에 필요한 자격증명이 있다 (Kaggle만 해당) |
| 최소 보장 | 실패해도 예외가 밖으로 새지 않고 빈 목록과 사유로 바뀐다 |
| 성공 보장 | 그 소스가 지금 열어 둔 대회 목록이 원본 형태로 돌아온다 |
| 트리거 | [[#UC-A1]] 2 |
| 패키지 | 수집 |
| 포함(include) | — |
| 확장점(extension point) | — |
| 일반화 | 소스마다 구현이 다르다. 인터페이스는 같다 |

**기본 흐름**

1. 소스별 조회 조건을 만든다. event-us는 행사유형 `대회/공모전`만 걸고 분야는 걸지 않는다.
2. 목록을 요청한다. 식별 가능한 User-Agent를 보낸다.
3. 여러 쪽에 걸쳐 있으면 다음 쪽을 이어 요청한다. 요청 사이에 간격을 둔다.
4. 원본 레코드 목록과 건수를 돌려준다.

**확장**

- **2a. 요청이 실패하거나 응답이 예상과 다르다**
  - 2a1. 정해진 횟수만큼 다시 시도한다.
  - 2a2. 그래도 실패하면 빈 목록과 사유를 돌려준다. 예외를 던지지 않는다([[#UC-A1]] 2a).
- **3a. 쪽이 예상보다 훨씬 많다**
  - 3a1. 정해진 상한에서 멈추고 그 사실을 기록한다. 배치가 [[CCR-PRD-001#N2]]를 넘기지 않게 한다.

**연관**: [[CCR-PRD-001#R1]] · [[CCR-PRD-001#R9]] · [[CCR-PRD-001#N4]] · [[CCR-SCN-001#S5]]

#### UC-S2 수집 결과를 공통 형식으로 맞춘다

| 항목 | 내용 |
|---|---|
| 범위 | 정규화 |
| 수준 | 하위기능 |
| 주 액터 | 배치 |
| 이해관계자와 관심사 | 참가자 — 노션의 날짜가 실제 접수 일정과 맞기를 바란다 |
| 사전조건 | [[#UC-S1]]이 원본 레코드를 돌려주었다 |
| 최소 보장 | 필수 값이 없는 레코드가 뒤 단계로 넘어가지 않는다 |
| 성공 보장 | 모든 레코드가 대회명·상세링크·접수마감일·출처·원천ID를 갖춘 같은 형식이 된다 |
| 트리거 | [[#UC-A1]] 3 |
| 패키지 | 정규화 |
| 포함(include) | — |
| 확장점(extension point) | — |
| 일반화 | — |

**기본 흐름**

1. 소스별 필드를 공통 이름으로 옮긴다. event-us의 접수시작일은 `register_start_date`, 접수마감일은 `register_due_date`에서 온다.
2. 날짜를 KST로 바꾼 뒤 시각을 버리고 날짜만 남긴다. 소스가 주는 값은 `+00:00` 오프셋이 붙어 있으나 실제로는 KST 시각이라, 변환 없이 날짜만 취하면 하루씩 어긋난다.
3. 상세 링크를 절대 주소로 만든다.
4. 대회명 앞뒤의 공백을 정리한다.
5. 공통 형식 레코드를 돌려준다.

**확장**

- **1a. 접수마감일에 해당하는 필드가 그 소스에 없다**
  - 1a1. 빈 값으로 둔다. [[#UC-S3]]이 이 경우를 버리지 않는다.
- **1b. 대회명이나 상세 링크가 비어 있다**
  - 1b1. 그 레코드를 버리고 기록에 남긴다. 노션에 넣어도 쓸모가 없다.
- **2a. 날짜 형식이 파싱되지 않는다**
  - 2a1. 그 날짜만 빈 값으로 두고 레코드는 살린다.

**연관**: [[CCR-PRD-001#R2]] · [[CCR-SCN-001#S1]]

#### UC-S3 접수마감이 지난 대회를 버린다

| 항목 | 내용 |
|---|---|
| 범위 | 선별 |
| 수준 | 하위기능 |
| 주 액터 | 배치 |
| 이해관계자와 관심사 | 참가자 — 참가할 수 없는 대회가 목록에 쌓이지 않기를 바란다 |
| 사전조건 | [[#UC-S2]]가 공통 형식 레코드를 돌려주었다 |
| 최소 보장 | 마감일을 알 수 없다는 이유로 대회를 잃지 않는다 |
| 성공 보장 | 남은 대회는 모두 지금 지원할 수 있다 |
| 트리거 | [[#UC-A1]] 4 |
| 패키지 | 선별 |
| 포함(include) | — |
| 확장점(extension point) | — |
| 일반화 | — |

**기본 흐름**

1. 실행 시점의 KST 날짜를 기준으로 잡는다.
2. 접수마감일이 기준일보다 이른 대회를 버린다.
3. 버린 건수를 기록에 남긴다.
4. 남은 대회를 돌려준다.

**확장**

- **2a. 접수마감일이 비어 있다**
  - 2a1. 버리지 않고 남긴다. 놓치는 쪽이 잘못 넣는 쪽보다 나쁘다.
- **2b. Kaggle의 상시 연습용 대회다**
  - 2b1. 마감일과 무관하게 버린다. `Getting Started`와 `Playground`는 마감일이 먼 미래로 잡혀 있어 2에서 걸러지지 않는다.

**연관**: [[CCR-PRD-001#R3]] · [[CCR-SCN-001#S7]]

#### UC-S4 이미 아는 대회를 걸러낸다

| 항목 | 내용 |
|---|---|
| 범위 | 선별 |
| 수준 | 하위기능 |
| 주 액터 | 배치 |
| 이해관계자와 관심사 | 참가자 — 같은 대회가 여러 행으로 쌓이지 않고, 지운 대회가 되살아나지 않기를 바란다 |
| 사전조건 | 노션 `대회목록`을 읽을 수 있다. 적재 이력 파일이 있다 (없으면 빈 것으로 본다) |
| 최소 보장 | 해가 다른 대회를 같은 대회로 묶지 않는다 |
| 성공 보장 | 남은 대회는 노션에도 이력에도 없는 것뿐이다 |
| 트리거 | [[#UC-A1]] 5 |
| 패키지 | 선별 |
| 포함(include) | — |
| 확장점(extension point) | — |
| 일반화 | — |

**기본 흐름**

1. 노션 `대회목록`의 모든 행을 읽는다.
2. 적재 이력 파일을 읽는다. 지금까지 배치가 넣은 대회의 키가 들어 있다.
3. 둘을 합쳐 `아는 대회` 집합을 만든다. 이력을 같이 보기 때문에 참가자가 지운 행도 아는 대회로 남는다([[#UC-A2]] 5a).
4. 후보 대회끼리 먼저 묶는다. 같은 소스 안에도 중복 공고가 있다.
5. 각 후보를 `아는 대회`와 견준다.
6. 어느 것과도 묶이지 않은 대회만 돌려준다.

판정은 세 단계다.

| 단계 | 판정 |
|---|---|
| 1 | 출처와 원천 ID가 같으면 같은 대회 |
| 2 | 대회명을 정규화해 완전히 같으면 같은 대회. `모집`·`공고`·`안내` 꼬리말, 대괄호 머리말, `(~9/20)` 같은 괄호 날짜를 떼고, `2026년`을 `2026`으로 맞추고, 공백과 기호를 없앤다 |
| 3 | **연도나 회차가 서로 다르면 다른 대회.** 여기서 끝낸다 |
| 4 | 남은 경우 정규화 대회명의 유사도가 0.80 이상이면 같은 대회 |

3단계가 없으면 `2026 한국관광 데이터랩 활용 경진대회`가 `2025 한국관광 데이터랩 활용 경진대회`와 0.94로 묶인다. 정작 올바른 짝인 `2026 데이터·AI 혁신 챌린지 통합경진대회`는 0.82라, 유사도 문턱만으로는 둘을 가를 수 없다.

**확장**

- **1a. 노션을 읽지 못한다**
  - 1a1. 판정 근거가 없으므로 적재를 하지 않는다([[#UC-A1]] 5a).
- **2a. 적재 이력 파일이 없다**
  - 2a1. 빈 이력으로 본다. 첫 실행이 여기 해당한다.
- **4a. 여러 후보가 한 덩어리로 묶인다**
  - 4a1. 접수 시작일·마감일이 더 채워진 쪽을 남긴다. 같으면 정해진 소스 우선순위를 따른다.
- **5a. 노션의 기존 행에 링크가 없다**
  - 5a1. 1단계를 건너뛰고 2단계부터 본다. 참가자가 손으로 넣은 행은 링크가 비어 있을 수 있다.

3. 남긴다/버린다와 한 줄 근거를 받는다.

**기본 흐름**

2. 값을 채운다.
3. 그 대회의 키를 적재 이력에 더한다.
4. 모든 대회를 처리한 뒤 적재 이력 파일을 저장소에 커밋한다.

| 노션 컬럼 | 값 |
|---|---|
| 기타 (title) | 대회명 |

**확장**

- **1a. 행 생성이 실패한다**
  - 1a1. 그 대회를 건너뛰고 사유를 기록한다. 이력에도 넣지 않아 다음 실행이 다시 시도한다.
- **2a. `출처`·`수집일` 컬럼이 없다**
  - 2a1. 컬럼을 만든다. 기존 행은 빈 값으로 남는다.
- **4a. 이력 파일 커밋이 실패한다**
  - 4a1. 실행을 실패로 끝낸다. 이력이 안 남으면 다음 실행에서 같은 대회가 다시 들어오지만, 노션에는 이미 있으므로 [[#UC-S4]] 1이 막는다. 참가자가 지운 대회만 되살아난다.
